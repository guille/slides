A talk in fifteen slides

Slides are just web pages

Press P for the presenter view · O for the overview · arrows to move

Welcome. The claim of this talk: a slide deck is a web page with a fixed-size stage and a cursor. Everything else is CSS.

This very deck is the demo: every feature I mention is on screen.

One canvas

1920 × 1080

Every slide is authored at exactly these pixels. Then the whole stage scales to fit.

Content never reflows. If it fits on my laptop, it fits on the venue projector. That one rule removes most "it looked fine at home" surprises.

Why the web?

Part one: why build slides on the web platform at all.

What you get for free

  • Plain text in git: diffs, reviews, blame
  • Real links, real selectable text
  • Any JS library, any live demo
  • Opens anywhere with a browser
Default step effect: each item fades in and stays. No data-effect attribute at all.

Slide software vs a web page

The usual way

  • Binary file, mailed around
  • Fonts missing at the venue
  • Demos are screenshots
  • Theme lives in a dialog box

This way

  • A folder of HTML and CSS
  • Fonts ship with the page
  • Demos are the real thing
  • Theme is a stylesheet
Split layout: heading spans both columns, then exactly two children. The right column uses the rise effect.
Simple things should be simple, complex things should be possible.
Alan Kay
This is the design goal. A slide with a heading and bullets needs nothing. A slide with a live canvas needs a few lines of JS.
02

How it works

Part two: the stage, steps, theming, presenter view and PDF.

The stage scales, the content doesn't

Window size

  1. Laptop 1440 × 900
  2. Projector 1024 × 768
  3. Phone 390 × 844
  4. Ultrawide 3440 × 1440

One transform: scale(). Letterbox the rest.

Live canvas wired with onSlide(): it starts animating on enter, stops on leave, and each step snaps the simulated window to a preset.

The list uses the highlight effect: always visible, accent while current.

Steps tell the story one beat at a time

  1. Mark it. Add data-step to any element.
  2. Style it. Pick an effect, or write your own CSS.
  3. Link it. #9.2 is slide nine, step two.
The dim effect: the current point is bright, earlier ones fade back so the audience knows where we are.

A whole deck is one file

<main class="deck" data-transition="fade" data-progress>
  <section data-layout="title">
    <h1>Slides are just web pages</h1>
    <aside class="notes">Only I can see this.</aside>
  </section>
  <section><li data-step data-effect="rise">…</li></section>
</main>
<script type="module">
  import { deck } from "./lib/deck.js";
  deck(document.querySelector(".deck"));
</script>
